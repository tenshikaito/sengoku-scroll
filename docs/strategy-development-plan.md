## 1. 开发顺序与范围

### 1.1 全项目开发顺序（严格串行）

| 顺序 | 阶段 | 状态 | 说明 |
|------|------|------|------|
| **1** | **大战略（策略）单机** | **当前** | 本文档 M0–M4 范围 |
| 2 | 立志传（RPG） | 未开始 | 策略 M3 完成后；**在策略基础上增量改造**（见 §10） |
| 3 | **策略多人联机** | 未开始 | **RPG 模式完成后**再启动（非策略 M3 后） |
| 4 | MMO | 未开始 | RPG 可玩里程碑后 |

**原则**：同一时间只做一个阶段；策略 **本文档不含多人联机实装**。

### 1.2 策略模式本期目标（一句话）

交付 **单机可玩的半回合大战略 vertical slice**：选势力 → 全国地图 → 内政/征兵/移动/方针 → **运输队后勤 + 信使制度** → 瞬间战斗与战报 → 简单 AI → 存档。**不包含**多人联机（整阶段延后至 **RPG 完成之后**）。

### 1.3 与现有代码的关系

| 已有 | 策略开发中的处理 |
|------|------------------|
| `SengokuScroll.Domain` 实体/移动/外交骨架 | 扩展并修复已知 Bug（见 design-document §3） |
| `SengokuScroll.Application` GameLoop/Director | 接入 `StrategyGameEngine` 配置 |
| `SengokuScroll.WebClient` Canvas 原型 | M2 起重构为 Vue + PixiJS 策略主地图 |
| 模式项目 `SengokuScroll.Strategy/` | M1 起按 §7 创建 |

### 1.4 迭代顺序与确认门（实装约束）

每个里程碑 **严格按后端 → 前端** 推进；**每完成一步须向负责人确认无问题后，再开始下一步**。

```
单步循环（每个功能切片重复）：
  ① 后端（Domain / Application / Strategy 系统）
  → ② 后端单元/集成测试
  → ③ WebApi 命令与 DTO
  → ④ 前端（Vue + PixiJS）
  → ⑤ 联调与试玩
  → 【确认门】负责人 OK → 下一小步
```

| 阶段 | 后端优先交付 | 前端跟进 | 确认门 |
|------|-------------|----------|--------|
| M1 | 地图加载、移动、日推进、运输队/信使 **实体骨架** | 暂不启动 | M1 后端+测试 OK |
| M2 | 移动/时间 API 稳定 | 主地图纵切 | M2 纵切可目视移动 OK |
| M3 | 瞬间战、方针+信使、自动后勤、AI、存档 | 预览/战报/后勤与信使 UI | M3 §3.2 可玩 OK |
| M4 | 平衡/内容/高级信使玩法 | 打磨与美术 | 按需 |

**禁止**：在未通过当前步确认门之前，并行开发下一步的前端或跨模块大改。

## 2. 玩家体验方针（全局）

以下原则 **适用于全部模式**，并作为策略模式实装与 UI 的最高约束。  
已在 [基本设计 §1.6](./design-document.md#16-玩家体验方针) 与 [共通界面设计 §1](./shared-ui-design.md#1-设计原则) 中同步。

### 2.1 核心表述

> **方便玩家操作与战略决策，减少在细节与微操上耗费精力。**

玩家时间应花在：**打哪里、何时打、外交取舍、资源分配、方针预设**；  
不应花在：**手动派遣/逐格指挥运输队、手动逐支派遣信使、重复确认、管理大量中间状态**。

### 2.2 机制层解读（2026-07-08 已确认）

| 设计概念 | 玩家侧体验 | 系统侧（后台自动） |
|----------|------------|-------------------|
| **真实后勤** | 地图上可见 **运输队实体**（与兵队同类、携带粮草物资）；单位详情显示「补给：充足 / 紧张 / 断绝」及 **在途运输**（如「🌾 800，运输队预计 5 日后抵达」）；胜率预览体现补给修正 | 系统 **自动** 从据点生成并调度运输队沿路径补给前线；玩家 **不** 手动点选运输队或规划粮道路线；断绝/紧张由 **在途队是否可达、是否被截、库存是否足** 等综合判定 |
| **间接指挥（NPC 单位）** | 为单位/部队 **预设方针** 或下达「进攻目标」「驻留区域」等 **战略级指令** | 单位按方针与 AI 自动执行；玩家不逐格微操 NPC 部队 |
| **信使制度** | 战报、外交文书、**远程方针/战略指令** 均以 **信使报告** 呈现；地图上可见在途信使（可选简略图标） | **同格免信使**：下达方与目标单位 **在同一格**（含同在据点内）→ 指令 **立即生效**；**异格需信使**：系统自动生成信使沿路径传递，**到达后** 方针/指令生效；战报同理经信使送达（到达前不可见详情） |
| **战斗方式（单机）** | 战斗触发时 **先选模式**：⚡ **瞬间（自动）战斗** 或 ⚔ **亲自指挥**；选自动则 **胜率预览 → 确认/取消 → 战报** | 瞬间战：方针匹配与确定性结算；**亲自指挥**：进入战术地图（**功能后期开发**，M3 仅预留选项/UI，实装随 RPG 战术地图） |
| **战斗方式（多人）** | 仅瞬间（自动）战斗 | 不阻塞其他玩家 |
| **经济** | 月度 **收支摘要**、据点 **一行状态**；建设/征兵用 **向导式表单** | 日/月自动结算税收、维护费、粮耗 |

### 2.3 UI 层约束

1. **决策点显性化**：凡影响胜负的操作，战前必须能预览后果（胜率、伤亡区间、补给修正）。
2. **默认值合理**：未设方针的单位使用势力默认方针；新单位默认「坚守」类保守方针。
3. **一键可达**：常用操作从主地图 **≤3 次点击** 完成（选单位 → 指令 → 确认）。
4. **情报可读**：用图标+短句（「补给断绝」「被包围」），避免裸表格堆砌。
5. **可跳过动画**：战斗结算、月度报告支持快速关闭。

### 2.4 明确不做（策略首版）

- 玩家 **手动** 派遣/操控运输队或信使（路线、护卫、逐格微操）  
- 仅显示「补给三态」而 **无运输队实体** 的纯抽象后勤  
- 异格方针/远程指令 **即时生效**（违反信使制度）  
- 逐日微操多支部队路径同步  
- 无预览的不可逆高风险操作  
- 策略 M3 实装 **亲自指挥战术地图**（选项可展示，功能延至 RPG 战术地图就绪后）  
- 8 人联机与 Lockstep（整阶段延后至 RPG 后，见 §1.1）

## 3. 策略模式目标定义

### 3.1 核心体验（不变）

参照 [strategy-detail-design §1](./strategy-detail-design.md#1-核心体验)：

- 控制一个势力，半回合制全国地图  
- 任意暂停、部署、推进时间  
- 战斗触发时单机可选 **瞬间（自动）** 或 **亲自指挥**；M3 实装前者，后者 **后期开发**（RPG 战术地图）

### 3.2 首版可玩标准（Definition of Done · M3）

| # | 标准 |
|---|------|
| 1 | 1 个剧本、2 个可玩势力（其余 AI），≥10 个据点的小地图 |
| 2 | 完整日循环：时间推进 → 单位移动执行 → 经济日耗 → 月度结算 |
| 3 | 玩家可：征兵、移动、攻击、设方针、查看情报与战报 |
| 4 | 瞬间战斗：战前选 **自动**（M3 可用）/ **亲自指挥**（占位）；自动路径：预览 → 确认 → 结算 → 战报（经信使）→ 更新地图 |
| 5 | 简单 AI：守家、边境巡逻、弱扩张 |
| 6 | 单机存档/读档 |
| 7 | 主地图 + 必要 Popup/情报/战报 UI 可玩（不要求 art 终稿） |

### 3.3 胜利与失败（首版简化）

| 结果 | 条件 |
|------|------|
| 胜利 | 占领指定目标据点（剧本配置）或消灭所有敌势力 |
| 失败 | 己方全据点沦陷或君主被俘（若已实现俘虏则启用，否则仅灭国） |

## 5. 功能范围：首版 / 延后 / 不做

### 5.1 M3 必须（In Scope）

| 系统 | 首版范围 |
|------|----------|
| 时间 | 半回合暂停/继续/调速；日推进 |
| 地图 | TileMap + 据点 + 单位；ZOC **简化**（相邻格即可） |
| 军事 | 移动、攻击、征兵（单兵种即可）、方针 6 种；**Unit 总将 + SubUnit 兵种构成**（出征编组时确定，非临战任命） |
| 战斗 | 野战 + 攻城；单机战前选 **自动/亲自指挥**（后者占位）；自动路径含胜率预览 |
| 经济 | 金 + 粮；月结；**运输队实体** + 补给 **三态** |
| 后勤 | 自动派遣运输队（地图可见）；玩家不可手动操控 |
| 信使 | 异格方针/远程指令/战报 **经信使**；同格（含同据点）即时 |
| 外交 | **仅** 战争/和平二元 + 同盟标记（足够触发战斗），完整 CB/和谈 → M5 |
| AI | 单档简单 AI |
| UI | 主地图、Popup、方针设定、战报、基础情报列表 |
| 存档 | 单机文件 |

### 5.2 延后（Out of Scope · 策略单机阶段）

| 系统 | 说明 |
|------|------|
| **多人联机** | **RPG 模式完成后** 单独阶段；设计见 strategy-detail §11、shared-detail §8.1 |
| 单人战术地图 | 战术地图在 **RPG 阶段** 首做（RPG 为策略增量） |
| 完整外交（CB、战争分数和谈、联姻） | M4 打磨或更后 |
| 气候/灾害 | M4 或更后 |
| 贸易路线/官办企业/关税（运输队货值） | M4-c |
| 信使截获/篡改 | M4 可选 |
| **亲自指挥战术地图** | **RPG 阶段**（策略 M3 仅 UI 占位） |
| 角色忠诚/叛变/人事全套 | M4 或更后 |
| 职业/卡片/剧情 | **RPG 阶段** |

### 5.3 明确不做（策略单机阶段）

- 手机端适配（见 design-document §1.4）  
- MMO 任意功能

## 6. 系统实现要点

### 6.1 真实后勤 — 运输队实体（StrategySupplySystem）

> **已确认**：后勤不是纯 UI 三态，而是与兵队同类的 **运输队实体** 携带粮草；**自动派遣**，玩家不手动指挥。

```
SupplyConvoy（地图实体，类似军事单位）
├── 属性：载粮量、出发据点、目标单位/区域、预计到达日、路径
├── 生成：系统检测前线单位需补给 → 从最近有库存据点 **自动** 生成运输队
├── 移动：沿寻路每日推进；可被敌军/ZOC/战斗 **拦截或摧毁**（M3 可简化拦截规则）
├── 到达：向目标单位/区域转移粮草 → 更新 Unit 本地粮/士气
└── 可见：主地图图标 + 单位详情「运输中：🌾 N（预计 X 日后到达）」

SupplyStatus（衍生状态，非唯一真相）
├── 充足：在途+本地库存满足需求，路径通畅
├── 紧张：在途延迟、库存偏低、或路径受威胁
└── 断绝：无在途队且本地耗尽，或路径被切断且无替代队可派出

玩家不可做：
├── 手动创建/取消运输队、改路线、附加护卫
└── 将运输任务交给信使（运输 **仅** 运输队负责）
```

#### 6.1.1 历史参照与消耗基准（设计常数）

以日本战国时代 **兵站（ひょうじょう）· 输送** 为参照，游戏内抽象为 **「合」（ご）** 粮单位（1 石 = 1000 合）：

| 参照项 | 史实口径（简化） | 游戏基准 |
|--------|------------------|----------|
| 出征兵士日粮 | 约 **1.5～3 合** 米/人/日 | `LogisticsConstants.DailySoldierRationGo` |
| 输送人夫日粮 | 约 **1～2 合**/人/日 | `LogisticsConstants.PorterDailyRationGo` |
| 默认运输队编成 | 人夫 + 护卫 | `DefaultPorterCount` / `DefaultEscortSoldierCount` / `DefaultConvoyCargoGo` |
| 在途日耗公式 | 人夫与护卫在途同样耗粮 | `Calculators.LogisticsCalculator` |
| 前线日耗公式 | 兵数 × 日粮 | `Calculators.LogisticsCalculator` |

**M1 实装**：常数见 `Constants/`；纯计算见 `Calculators/`；判定见 `Rules/`；改实体见 `Actions/`。

#### 6.1.2 运输队被毁（已确认默认）

该批在途粮草 **全损**；目标单位补给 →「紧张」；系统自动从最近有库存据点 **再派一队**（若路径可达）。

### 6.2 方针、间接指挥与信使制度（StrategyMessengerSystem）

> **已确认**：远程方针/战略指令遵循信使制度；**同格（含同在据点内）免信使**。

```
指令下达判定：
├── 玩家与目标单位 Location 相同（同一 Tile / 同一 Stronghold 格）
│   └── 方针/移动/攻击等 → 立即生效（下一事件处理）
└── 不同格
    ├── 系统自动生成 Messenger 实体，携带 OrderPayload（方针变更/进攻目标等）
    ├── 沿路径移动，到达后写入目标单位 PendingOrders → 生效
    └── UI 显示「信使传递中（预计 N 日）」

间接指挥（NPC）：
├── 玩家设方针 + 战略目标（如「进攻尾张城」）→ 经 § 上信使规则送达
└── 到达后由 StrategyAISystem / 默认逻辑生成路径，玩家不逐格微操

玩家直属单位：
├── 同格：可直接移动/攻击
└── 异格：移动/攻击命令同样可经信使（与方针同一套 MessengerSystem）
```

#### 6.2.1 信使向运输队传递假情报（已确认 · M3 骨架 / M4 完整）

谍报/外交 Advanced 玩法：**敌方或己方间谍信使** 可将 **假情报** 送达 **在途运输队**（非玩家手动点选路线）：

```
FalseIntelligence → SupplyConvoy
├── 触发：Messenger.PayloadType = FalseIntelligence, TargetConvoyId 指向运输队
├── 效果（M3 简化）：运输队改向错误据点/停留原地 N 日，载粮继续日耗
├── 发现：抵达错误地点或超过预计日数 → 补给转「紧张」，事件通知
└── M4 可选：截获信使、反制、护送运输队提高抗欺骗
```

**与方针信使区分**：假情报 **仅作用于运输队**；方针/战报仍走 §6.2 主规则。

### 6.3 信使与战报/外交

| 类型 | M3 行为 |
|------|---------|
| 方针/远程指令 | 异格 **必须** 经信使（从 **当主所在格** 出发）；同格即时 |
| 战斗结果 | 攻击命令 **日推进** 结算 → **战报信使** 自 **己方参战部队格** 向当主回程（**当日不移动**，次日出发）→ 抵达后 **解锁战报对话框** + 左上消息区一行摘要；同格免信使则即时送达 |
| 外交 | 文书经信使（M3 可简化为固定延迟公式）；同格会面即时 |
| 运输粮草 | **仅运输队**，不经信使 |
| **假情报** | 信使 `FalseIntelligence` 可作用于 **在途运输队**（改向/停留，§6.2.1） |

/settings 可预留「信使速度倍率」；**不**提供「关闭信使即时到达」以免破坏制度（除非调试模式）。

### 6.4 战斗方式与瞬间战

**单机战斗触发流程**（M3-b 实装）：

```
攻击流程
├── 指令 Popup：移动 / 攻击 / 方针（不在 Popup 显示 AP 不足文案）
├── 攻击：选相邻敌军 → preview-battle → 战斗确认对话框
├── 确认 → POST attack-order（排队，不即时开战、不扣 AP）
├── 推进日期 → StrategyBattleResolutionSystem 结算（扣 AP、单方/互攻 AP 先手定攻方）
├── 双方各派战报信使（自各自部队格 → 当主，次日移动）；败方 AI 按方针撤退
└── 信使抵达当主 → Events[].BattleResult → 通知托盘打开战报对话框
```

AP 不足：preview/attack-order 返回 `ApNotEnough`；前端 **对话框 + 信息栏** 提示（攻击按钮仍可点）。

多人：仅瞬间（自动）战斗；守方方针自动匹配；确定性种子（为日后联机预埋）。

详见 [strategy-detail-design §6–§9](./strategy-detail-design.md#6-自动战斗系统)。

### 7.4 代码规范（M1 起适用）

| 类型 | 目录/命名 | 规则 |
|------|-----------|------|
| **常量** | `*/Constants/*Constants.cs` | **仅** `const` / `static readonly`；**禁止**方法 |
| **纯计算** | `*/Calculators/*Calculator.cs` | 无状态静态类；入参→数值，**不修改**游戏状态 |
| **业务规则** | `*/Rules/*Rules.cs` | 无状态静态类；判定/策略（如是否需要信使） |

| **地图坐标** | `Domain/Actions/MapLocationActions.cs` | 修改 Unit/Character/Stronghold 坐标时 **必须** 经此同步 `GameMapData` 格点索引 |
| **有状态辅助** | `*/Helpers/*Helper.cs` | 可 `new`；持有上下文或跨步骤状态（按需） |
| **业务注释** | 全部业务代码 | 实体字段、枚举成员、Calculator/Rules/Actions 公开方法、System 业务分支均须注释 |
| **测试** | `*.Tests` | 涉及业务场景的 Arrange/断言须行内注释说明「测什么、期望什么」 |

```
SengokuScroll.Strategy/
├── Constants/
├── Calculators/
├── Rules/
├── Actions/
├── Helpers/            ← 按需
├── Time/               ← 控制器等领域服务（可 new 或 DI）
├── Systems/
└── Extensions/
```

> **不再使用** `Utils/` 存放业务逻辑；仅技术无关的通用工具（若有）可保留 `*Utils` 命名。
