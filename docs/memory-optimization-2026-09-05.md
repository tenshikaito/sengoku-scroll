# 内存优化与验收 — 2026-09-05

## 已实现

- 行情按 `(ObserverForceId, SubjectStrongholdId)` 索引，仅保留最新收到的报价。同日仍取第一条，较晚收到的旧日行情仍遵循原有“收到日”语义。恢复旧存档时压缩历史；此表不是玩家的永久价格历史图表。AI 查询不再扫描全部历史。
- 日初清除已不存在单位的过境收费标记，保留现存单位（含暂停、返程）的标记；待征税金额不受影响。
- 信使更新结束后删除找不到对应载体的暂存报告；仍在途载荷不删。
- 房间文件使用流式反序列化，避免先构造整份 UTF-16 字符串；行情压缩同时减少存档对象和 JSON 分配。未重写 v2 格式，仍含完整世界及兼容字段。
- 地图四层重绘时销毁移除的对象及子对象；异步 Pixi 初始化完成后检查卸载代次，过期实例立即销毁。
- 默认开启持久化时，每 30 秒检查房间。全员离线、最后活动已超过 `StrategyMultiplayer:IdleHibernateSeconds`（默认 600 秒）才休眠。先成功保存，再释放世界；房间元数据和凭证常驻，列表不会唤醒世界，后续访问 Host 按需恢复。持有请求 Gate 的房间不休眠。禁用持久化或将该选项设为 0 可关闭休眠。
- 休眠写盘失败保留当前世界并进入既有 StorageError；唤醒失败保留磁盘快照，不擅自重建剧本覆盖进度。

## 保留边界

战报成功/失败通知去重键仍随历史增长：本轮不盲目设置数量上限，以免仍在途的旧信使重复投递。需要稳定报告生命周期标识和终结条件后才能进一步安全压缩。私人信箱仍按每势力 4096 条保留，未确认消息会占用内存；这是有界设计，不是无限泄漏。

尚未实施渲染对象池、真实浏览器长时间堆/显存分析，也未将房间服务改为多进程或多节点。服务启动仍恢复已保存房间，闲置检查再将其休眠；启动峰值尚可进一步优化。不要在业务循环中调用强制 GC；本轮强制 GC 仅出现在隔离诊断程序。
