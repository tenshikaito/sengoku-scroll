# 1–8 人大战略联机 MVP

## 当前能力

- 本地持久化大厅：创建、列出、加入和退出房间；服务重启自动恢复已保存房间。
- 每个房间独立拥有一个 `StrategySimulationHost`、世界、随机种子和 DI 作用域。
- 势力独占：同一势力同时只能由一名玩家占用。
- 请求身份：房间号与 192-bit 随机玩家令牌。
- 服务器权威：客户端沿用现有战略 API，但服务端在房间锁内切换观察/行动势力并执行全部规则校验。
- 命令去重：联机写请求要求唯一 `X-Sengoku-Command-Id`，按玩家隔离，房间最近保留 2048 个命令号。失败命令的缓存节点完整移除；通知失败不回滚已提交指令的去重记录。
- 统一时钟：所有在线玩家准备后只推进一天，随后清空准备状态。准备后再次成功修改命令，会取消本人的准备；失败命令不影响准备状态。
- 断线容错：认证 HTTP 心跳或操作续订在线状态，默认约 90 秒无活动后不再阻塞准备。`Strategy:Multiplayer:ConnectionLeaseSeconds` 可配置为 15–3600 秒，启动时验证。单个 SignalR socket 断开不立即踢掉仍有其他连接的玩家。
- AI 托管：无人占用的势力由 AI 控制；真人势力的当主不被人物 AI 接管。
- 独立情报：世界状态在映射前切换到请求者势力，进行迷雾和谍报裁剪；完整多人模拟视角独立性仍需进一步验证，不能据此保证不存在所有情报侧漏。
- 同步：服务端提供 SignalR 房间组和 `WorldChanged` 通知；内置网页每 2.5 秒发送轻量心跳，只在世界版本变化时拉取完整状态，不重叠轮询，也不覆盖请求期间已经更新的状态。
- 重新加入：浏览器保存房间凭据，刷新页面后调用 reconnect 恢复会话。
- 请求截止：读请求 15 秒、写请求 120 秒，覆盖等待响应体；不自动重试写操作。超时可能发生在提交之后，客户端应先确认状态。
- 私人信箱：战报、战略信使与经济月报/年报按势力投递，未在线势力也保留消息；统一日结不再采用最后准备者的视角。未标明接收方的旧诊断消息不会广播。
- AI 城池情报保存最后可见的归属、防御和总驻军；90 游戏日后防御/驻军退回估计值（50 / 1000），不读取隐藏城池实时数值。联机视野策略与请求者身份无关，援防目标只考虑已观察到的威胁。

## 请求约定

进入房间后的既有 `/api/strategy/*` 请求需要：

```http
X-Sengoku-Room-Id: 10位房间代码
X-Sengoku-Player-Token: 玩家私有令牌
X-Sengoku-Command-Id: 每个写命令唯一随机字符串（1–100 字符）
```

响应包含当前 `X-Sengoku-World-Version`。`ready` 请求必须提交 `{ "ready": true, "expectedTurn": 房间当前turnNumber }`，过期或缺失回合号返回 409。直接加载剧本、推进日期、即时战斗、单机存档、全局诊断与任意谍报注入接口在房间上下文中返回 403；规则按路由解析后的动作判定，尾斜杠不能绕过限制。

大厅 API：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/multiplayer/rooms` | 房间列表 |
| POST | `/api/multiplayer/rooms` | 创建房间并返回房主凭据 |
| GET | `/api/multiplayer/rooms/{roomId}` | 房间与玩家准备状态 |
| GET | `/api/multiplayer/rooms/{roomId}/heartbeat` | 认证并续订在线状态，返回版本与房间信息，不构造完整世界 |
| POST | `/api/multiplayer/rooms/{roomId}/join` | 占用未被选择的势力 |
| POST | `/api/multiplayer/rooms/{roomId}/reconnect` | 使用原玩家 ID 和令牌重连 |
| POST | `/api/multiplayer/rooms/{roomId}/ready` | 设置准备；全员准备时推进一天 |
| POST | `/api/multiplayer/rooms/{roomId}/leave` | 主动离开并释放势力 |
| GET | `/api/multiplayer/rooms/{roomId}/events` | 认证后读取本势力最多 100 条未确认消息，不删除消息 |
| POST | `/api/multiplayer/rooms/{roomId}/events/ack` | `{ "sequence": N }` 确认本势力不大于 N 的消息，重复确认安全 |
| GET | `/api/multiplayer/scenarios/{scenarioId}/forces` | 创建房间前列出可玩势力 |

SignalR Hub：`/hubs/strategy`。客户端连接后调用 `JoinRoom(roomId, playerToken)`，服务端使用 `RoomJoined` 和 `WorldChanged` 事件通知房间变化。

## 并发与多核边界

- 不同房间可以由 ASP.NET Core 线程池并行处理，天然利用多核。
- 单个房间使用 `SemaphoreSlim` 串行化命令、准备推进和玩家状态修改。
- 房间内部继续使用 `StrategyParallelWork` 处理只读视野、AI 感知、DTO 和地图投影。
- 进程内同一时刻只有一个区域展开并行；争用时其他区域直接顺序计算，避免嵌套等待和重复扩张线程预算。
- 世界写操作仍固定顺序提交，保持同种子回放确定性。

不要把一个房间内的两个玩家命令并行写进 `GameWorld`。扩展到多进程时，应按 `RoomId` 将整个房间固定路由到一个 actor/节点。

## 局域网运行

开发环境：

```powershell
dotnet run --project .\SengokuScroll.WebApi\SengokuScroll.WebApi.csproj --launch-profile lan
```

开发环境另开终端在 `SengokuScroll.WebClient` 运行 `npm run dev`，玩家访问主机 5173 端口。5100 在 Development 下不托管网页。Vite 代理保留浏览器 Host，以供后端校验局域网请求 Origin。

发行版默认监听 `http://0.0.0.0:5100`。主机自己访问 `http://127.0.0.1:5100/`，其他设备访问 `http://主机局域网IP:5100/`。只应在可信局域网和 Windows“专用网络”防火墙范围内开放端口。

API 和 Hub 默认拒绝不受信任的浏览器 Origin；同源访问放行，Development 另外允许 loopback 的 5173 前端。确需分离前后端或反向代理时，在 `Strategy:AllowedBrowserOrigins` 数组中填写明确的 `http(s)://主机:端口`，不得使用 `*`。正常同源代理应保留外部 Host/协议；配置必须与实际部署匹配。来源校验不是身份认证，无 Origin 的非浏览器客户端仍可访问单机接口，不可直接暴露到公网。

## 当前限制

- 房间使用单进程、本地文件快照，不是数据库事务集群；必须备份存储目录并保留原浏览器会话凭据。
- 令牌是访客房间凭据，不是正式账号系统；没有密码、JWT、封禁或角色所有权数据库。
- 当前没有 TLS、公开互联网匹配、NAT 穿透、邀请链接或反作弊遥测。
- SignalR 服务端通知已经提供，内置客户端以轮询为可靠基线，尚未引入 SignalR JavaScript 客户端包。
- 已覆盖反向准备顺序、各势力消息隔离、完整重启存档一致性；这些回归不等于所有剧本、难度和长期多人博弈已无情报侧漏。战术接触与驻城守备仍采用当地实时规则，尚无统一的“城主向当主延迟传递 AI 军事情报”模型。
- 私人信箱每势力最多保留 4096 条未确认消息，超限丢最旧消息并提示截断；不是永久聊天/战报档案。浏览器展示后自动确认，刷新会清空本页已展示的消息栏。
- 联机存档槽仍主动禁用；房间快照自动保存，没有追加式命令日志、跨版本迁移工具或多节点故障切换。
- MMO 的账号、聊天、长期世界、分区、国战实例和数据库不在此 MVP 范围内。

## 房间重启恢复与运维

默认 `Strategy:Multiplayer:PersistenceEnabled=true`，`StoragePath=App_Data/multiplayer-rooms`（相对于服务内容目录，也支持绝对路径）。目录不得位于 `wwwroot` 下；同一路径仅允许一个服务进程持有写锁。快照包含私有令牌和完整世界，禁止提交 Git、通过静态服务公开或发送给其他玩家。

创建、加入、退出、准备、成功世界命令和消息确认都会在房间门锁内保存。先写同目录临时文件、刷盘，再替换原文件。保存包含世界、运行时台账、各势力探索/侦察记录、信箱、投递去重键、玩家凭据、回合和最近 2048 个命令 ID。心跳不触发整局磁盘写入。

重启后玩家均为离线且未准备；原凭据重连后恢复真人控制。所有人离线不会自动推进；有人继续准备推进时，离线势力由 AI 接管。最后一名玩家主动退出会删除房间快照，不再恢复该房间。

损坏快照会记录警告并原样保留，其他正常房间继续恢复。持久化失败返回 `503 / RoomStorageFailed` 并暂停该房间；修复磁盘/权限后重启，恢复最后一次成功保存的状态。失败请求不要盲目重试。快照替换不能代替停服备份，也不能保证物理磁盘损坏或极端断电下的数据安全。

消息读取与确认均由令牌决定势力，客户端不能指定他人 ForceId。传输采用至少一次交付：确认失败会补收，同一网页会话按序号避免重复展示；页面恰好在展示后、确认前崩溃时可能重新展示一次。
