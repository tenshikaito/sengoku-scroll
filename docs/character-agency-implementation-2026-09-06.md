# 人物行为机制首批实施记录

总体方案见 [人物行为机制设计](character-agency-design.md)。本轮是统一决策基础及五类行为接入，不是全部人物系统完成。

## 实际接入

- `CharacterDecisionRules.Capture` 从本人属性、本人对目标的有效关系、本人记忆提取标量快照；`Evaluate` 不访问世界、不写实体、不用随机数。
- 社交 AI 使用候选分数而非单纯好感排序；低于门槛可以不社交。同地点分组索引，排除正在休息/移动/执行任务的人，排除双向冷却目标，再按分数和 ID 稳定选人。
- 婚约 NPC 回应使用综合分；成年人、非近亲、单身、同地点、AP 等仍独立检查。亲疏或信任为负直接拒绝；不够积极时等待而不是强行同意。真人当主不自动回应。
- 忠诚仍分散到每周一天结算，每次最多 +1 / −2；已到数值边界且没有实际变化时不写“忠诚变化”事件。
- 叛离意向加入重义制约与滞回：进入意向分 ≥80，保留意向分 ≥65，并须忠诚 ≤35、对当主亲疏 <0。仍保留至少 30 日预警与原有个人投奔执行约束。并不新建叛乱势力。
- 解围主将根据慎重、勇气、对本家城池负责人的关系及智谋调整现有最低胜率门槛。无主将资料时保留原阈值。正常 AP、路径、同格兵力比和战斗规则不变；一般战斗评分尚未整体迁移。
- `RecentDecisions` 完整存档，按行为类型覆盖，最多 5 条；只向本势力人物 DTO 输出。前端可查看贡献与结果。没有将隐藏敌人性格、私人金库加入择偶评分。

## 可复核公式（v1 平衡参数）

所有除法为 C# 整数除法（向零截断）。属性钳制 0–100，亲疏/信任/心情钳制 −100–100。下表 `中心值(x)=x−50`。每项贡献单独保存，分数为各项之和。

| 行为 | 分数构成 | 决策门槛 |
| --- | --- | --- |
| 社交 | 20 + 亲疏/2 + 信任/4 + 中心值(温和)/5 + 中心值(重义)/5 + 心情/10 − (100−体力)/5 − 近期重复交谈 | ≥10，合格候选取最高分 |
| 婚约回应 | 亲疏×3/4 + 信任/2 + 中心值(重义)/5 − 中心值(慎重)/5 + 心情/10 − 近期拒绝 | ≥60；硬条件单独检查 |
| 忠诚演化 | 亲疏/2 + 信任/4 + 中心值(重义)/5 − 中心值(野心)/5 + 心情/10 | ≥30 时 +1，≤−30 时 −2，否则保持 |
| 叛离意向 | 50−忠诚 − 亲疏/2 + 野心/2 − 重义/2 | 新意向 ≥80，已有 ≥65；资格与出路另查 |
| 解围风险偏移 | 中心值(慎重)/5 − 中心值(勇气)/5 − max(0,亲疏)×重义/1000 + (100−智谋)/10 | 原最低胜率 + 偏移，钳制 15%–70%；不是成功率修正 |

比如双方关系条件相同（亲疏 60、信任 30、心情 0、无近期拒绝），重义 100/慎重 0 的婚约分是 80，而重义 0/慎重 100 是 40；NPC 会分别同意和等待。高魅力仍通过原会面执行规则影响关系效果，不直接等价为对方愿意结婚。

Principle 理想倾向没有被解释成道德值，尚待具体价值冲突事件；Hobby/Drinking/Fortune 本轮不参与这五类评分。动态长期目标与成长不冒充已实现。

## 记忆与兼容

- 同对象 7 日内 Talk 每条按 `7−年龄` 累加，最多扣 14 分；同对象 60 日内 MarriageDeclined 取最大 `12−年龄/5`，最多扣 12 分。
- 拒绝记忆不分双方，因为现有记录未区分“我拒绝”与“被拒绝”，统一表示近期拒绝经历。未来结构化事件可细分。
- 未来日期不生效，到期不生效；不修改关系基线，不重放已发生的赠礼/结婚效果。旧记忆仍为最近 64 条，因此淘汰也会移除相应短期影响；长期关键记忆另立项。
- 原 v2 存档缺少 RecentDecisions 时默认空；现有冷却、婚约、预警字段继续使用。更新后下一次 AI 日结算使用新规则，旧预警依新滞回条件复核，不能保证跨版本行为完全一样。
- 决策 UI 不是已执行事件：例如“有投奔意向”仍需满足实际出路；解围的风险阈值也不能代替兵力和路径检查。

- 新增 15 项后端测试：性格反事实、实际 NPC 婚约分歧、记忆衰减与无重复结算、纯评分、贡献求和、有序并行、决策上限、JSON 持久化、多人隐私、重复日结算、休息保护、稳定同分选择、跳过冷却、叛离滞回与取消。
- 519 项 .NET 测试；14 项前端回归及生产构建，前端接线检查不代替真人浏览器完整玩法测试。
- 本地候选包 `build/character-agency-20260906`（依赖 .NET 10，已嵌入前端）通过实际进程多人重启 8/8：静态客户端、双人就绪、进程重启、完整玩家状态、私人邮箱、持久化去重、回执与最后离房清理。本轮尚未提交或推送 Git。
- 四世界 ×365 日，调度上限 1/11，八份哈希均为 `3F3A81C7F56F4570C3D322F0DB1B057818AE991261B277D2F78C1B9B85D050A1`。这验证不同并行度的结果一致，不表示世界内所有系统已并行。
- 本机单次测量：上限 1 用时 4.884 s，上限 11 用时 4.421 s；前者与测试进程有重叠，不能据此认定稳定加速比。小剧本社交候选通常不足并行门槛，局部并行收益需大场景独立基准验证。
