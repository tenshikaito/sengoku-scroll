# 多人可靠性与情报修复（2026-09-05）

本轮对应三项获准工作：私人战报/经济报告、房间重启恢复、AI 情报公平性。只修改本地项目并生成测试发行包，未推送 GitHub、未部署公网。

## 已交付

- 日推进脱离最后准备者的视角，返回状态再按请求者裁剪；准备响应不携带全局事件和战斗明细。
- 按势力信箱、序号分页领取、幂等确认、每势力 4096 条上限。月报/年报、贡纳、贸易、征兵和信使消息有明确接收方；无接收方的旧诊断不广播。
- 战报信使归属、收件居城、战略事件去重按势力处理。在途报告、已投递去重键与私人信箱随存档保存；不同日期的相同战略事件文案不再被永久去重。
- 原子文件快照保存世界、各势力探索/侦察、台账、访客凭据、回合、版本和命令去重。启动恢复，损坏文件保留，磁盘失败返回 503 并暂停房间；最后退出删除房间，同一目录禁止多进程写入。
- AI 进攻使用敌城最后可见的归属、防御和总驻军；隐藏增兵或易主不直接改变目标评分。情报过 90 日后防御/驻军采用估计值；联机各势力使用相同开局规则与自己的当主位置；援防选城只计入已观察威胁。
- 保持不同房间并发、只读阶段受控并行、世界写入固定顺序。信箱采用有界队列，不逐条复制全部历史；心跳不整局刷盘。

## 测试额外发现并修复

1. 大额税赋万分比乘法溢出为负数，恢复时又被过滤：改为 64 位中间值及输出边界保护。
2. 溃败处理把子编制 ID 查进部队表，编号重叠时无限递归崩溃，亦可能误处理其他部队将领：改查 `SubUnits`，不再递归。
3. 人物熟练度 `Level` / `Exp` 是字段，默认 JSON 遗漏，重启后变零：明确纳入序列化，增加恢复后角色视图一致性检查。旧存档已经遗漏的经验无法凭空恢复。
4. 贡纳台账按收件势力拆分，普通补给不计为贡赋到账。

## 保留边界

仍适合可信局域网验收，不宜直接公网开放。尚无正式账号/凭据找回、TLS、限流、追加式事务日志、多节点恢复、长期版本迁移工具。战术接触和驻城守备使用当地实时规则，尚无统一的“所有 AI 情报均经信使延迟汇报”模型；多剧本、多难度的长期公平性仍需实玩验收。

信箱是有保留上限的至少一次交付，不是永久档案；关闭浏览器标签页可能丢失访客凭据。存储异常后恢复最后成功快照，不保证极端断电或硬件故障下零丢失。详细配置、备份和操作约定见 [多人说明](multiplayer-mvp.md)。
