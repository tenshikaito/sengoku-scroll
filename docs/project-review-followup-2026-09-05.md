## 修复清单

| 范围 | 问题与处理 |
| --- | --- |
| 浏览器来源 | `AllowAnyOrigin` 配合无认证单机 API 允许不受信任网页访问本机游戏。新增 API/Hub Origin 检查及明确允许列表，检查在请求执行前完成，不仅是省略 CORS 响应头；Vite 保留 Host 支持 LAN 同源代理。无 Origin 的脚本客户端依旧可访问，不能代替账号认证 |
| 联机身份 | 玩家令牌存在但缺少房间号时，原来落入单机世界。现在拒绝该不完整身份，不再默默切局 |
| 准备与编辑 | 已准备的玩家仍可修改命令而保持准备，可能在未重新确认时推进。成功修改后取消该玩家准备，失败命令不取消 |
| 联机诊断泄漏 | ready 日结返回包含全局诊断计数和潜在服务器文件路径。现在清空这两个字段；已有直接诊断接口限制保持不变 |
| 心跳 | 固定 12 秒租约容易在后台计时器节流时误判。改为默认 90 秒、启动校验 15–3600 秒配置。并不保证所有后台浏览器或长时间冻结均不会掉线 |
| 请求卡住 | 两个前端请求入口均缺少截止时间，心跳在途标志和加载状态可永久卡住。读 15 秒、写 120 秒，覆盖响应体解码，并主动取消网络请求；写命令不自动重试，提示先确认服务器状态 |
| 应用循环 | 并发 Start/Stop 缺少同步；故障任务停止后未清理，无法再启动。生命周期加锁并在 finally 清理；旧 Stop 不能清掉新任务；暂停改成异步等待，间隔计时改为单调时钟 |
| 剧本加载 | 当前世界在新剧本解析之前就被释放。改为先构造、验证新局，成功才释放旧局；失败清理临时作用域并保留原局，bootstrap 初始化失败也释放容器 |
| 年度人口 | 玩家/观察势力不存在时经济系统提前返回，导致全世界年度人口变化被跳过。人口更新与报告观察者分离，保留按原规则统一更新 |
| 日志性能 | 每世界新建控制台日志器，高频移动使用 Information、普通 AP 不足使用 Warning，长局产生大量控制台输出。改为复用应用日志工厂、移动细节使用 Debug，独立仿真默认静默 |
| 诊断配置 | 仿真没有接收外层日结/AI 选项，默认 IOptions 注册还会遮蔽 Configure。修复配置传递和注册；启用文件时按世界会话分目录，避免混写；世界释放不能销毁共享日志工厂 |
| 多核批量 | 刚达到阈值的小任务也申请整机预算。改成每工作线程至少分配一批、至少两批才并行，保留进程内非阻塞并行区域门；增加 `SENGOKU_MAX_PARALLELISM` 上限和独立基准 |

## 仍未解决的重点

1. **多人私人报告与模拟观察者耦合（P1）**：ready 仍在最后准备者视角下日结；经济/战报生成、贡纳台账仍有单玩家假设。需要按势力的持久事件、确认游标、断线补发，以及不同准备顺序的完整存档对照。本轮只修掉诊断字段泄漏，没有声称解决私人报告。
2. **房间持久化与回收（P1）**：只存内存，服务器重启丢局；未主动退出的全离线房间没有快照/过期回收。不能贸然删除玩家的局来释放名额。
3. **视野与 AI 公平性（P1）**：军事 AI 据点感知仍可能读取实时动态对象；视野初始化对默认玩家与其他势力有不同规则，Character 模式还依赖当前当主上下文。需要完整势力情报快照与不同加入/准备顺序测试，当前不能保证严格公平联机。
4. **公网生产化（P1/P2）**：来源检查不是认证。仍缺账号、邀请权限、TLS、持久反重放、限流、多节点房间路由、完整安全验收；只适合可信局域网原型。
5. **前端体验与结构（P2）**：巨型 Strategy.vue、房间准备状态呈现、过期房间自动提示、完整双浏览器端到端测试仍需推进；当前 ready 客户端先取服务器最新回合号，并未将准备意图严格绑定到玩家已看到的世界快照。
6. **性能与内容验收（P2）**：缺大地图、不同 CPU、长断线/后台节流、真实多设备数据；建设、气候灾害、深层角色内容与正式美术/平衡不是这轮缺陷修复的已完成项。
