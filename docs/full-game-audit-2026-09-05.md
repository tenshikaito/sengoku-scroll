# 战国绘卷全游戏审计（2026-09-05）

## 结论

当前仓库已经从“框架和分散系统”推进为可构建、可测试、可连续运行一年的单机策略原型。核心玩法链路没有发现阻止本地试玩的已知错误；本轮发现的确定性、存档字段、谍报串势力、AI 观测范围和高速观战开销问题均已修复。

它还不是内容完整的成品。最主要的未完成项是敌方据点动态情报记忆、建设/灾害/气候、深层角色事件、更多剧本与正式美术，以及设计文档中的 RPG/MMO 后续阶段。

## 本轮代码与设计修正

### 游戏闭环

- 新增全势力 AI 观战开局，并贯通请求、运行时元数据、存档会话和前端状态。
- 新增战役状态与统一进度，区分进行中、胜利、失败和观战。
- 新增五步首次教学与可重复打开的帮助入口。
- 角色关系从只展示数据推进到可交谈、赠礼；双方关系、信任和情绪会变化。
- `GameTask` 从空壳变为带类别、目标、状态、剩余量和完成语义的任务基础；加入婚姻、求仕、久仕、名声和统一目标追踪。
- 存档补齐角色金钱、行动力、生命和情绪，避免读档后人物状态重置。

### AI、情报与确定性

- AI 决策先刷新本势力视野，只把已观测敌军交给军事规则，不再直接枚举所有敌军。
- 全势力视野台账独立维护；人物与部队观察者不再误用玩家当主。
- 谍报台账由“目标”键改为“观察势力 + 目标”键，避免多势力情报互相泄漏；旧存档的无观察者记录自动归入当时玩家势力。
- 所有仿真路径移除 `HashCode.Combine`，改用稳定 FNV-1a 组合；疾病掷点也由 `Random.Shared` 改为剧本种子、日期和人物共同派生。

### 多核与吞吐

多核优化采用“并行纯计算、串行提交”边界：

1. 每个势力的视野快照互不写共享世界，在势力数不少于 4 且机器有多核时使用 `Parallel.For`。
2. AI 敌情从“每单位重复扫描全地图”改为“每势力一次”；不同势力并行感知，单位行动仍按固定顺序执行。
3. 势力、据点、单位、人物及大地图格数组达到阈值后并行映射，并按输入索引输出以保持实体 ID 顺序。
4. 人物目标先一次聚合领地统计，再按人物并行刷新，消除逐人物重复扫描。
5. 快照计算完成后按势力 ID 固定顺序写入台账，避免竞态与回放不一致。
6. 高速观战使用 1–31 日批量推进 API，按日保持原系统顺序，只在批次末映射一次完整世界 DTO。

没有把经济、战斗、占领等会相互影响的系统粗暴并行化。此类写共享状态的日内系统若直接多线程，会使结果依赖线程调度，破坏存档复现、测试和未来联机同步。以后适合继续并行的是寻路候选评估、AI 评分、只读统计和资源解码，提交阶段仍应确定性排序。

## 全量检查结果

- C# 解决方案可编译，项目警告已清零。
- 全套单元与 API 集成测试 394/394 通过（Application 1、Strategy 377、Web API 16）；新增全年全 AI 稳定性、并行确定性、批量推进、观战、人物互动、战役状态、稳定哈希和情报隔离覆盖。
- 前端 TypeScript 检查和 Vite 生产构建通过。
- 生产依赖审计无已知漏洞。
- 静态扫描未发现运行时代码中的 `NotImplementedException`；测试示例与注释中的占位不影响游戏。
- 仿真中的非确定性散列和共享随机源已清除；战术局部 `Random` 均由固定种子创建。

## 仍存在的设计缺口与风险

| 优先级 | 范围 | 当前情况 | 建议 |
| --- | --- | --- | --- |
| P1 | AI 据点情报 | AI 知道据点位置以保证战略可行动，但仍能接触目标据点的精确动态对象 | 建立按势力保存的据点情报快照、可信度与过期时间，AI 评分只读快照 |
| P1 | 内容与平衡 | 只有一个小剧本，全年稳定不代表大型地图数值平衡 | 加入 3–5 个规模梯度剧本，并做多种种子 3–10 年仿真 |
| P2 | 内政事件 | 建设、灾年、掠夺、气候和设施荒废未形成闭环 | 先落地数据驱动事件与建设队列，再接天气修正 |
| P2 | 角色叙事 | 有关系变化和目标追踪，但事件链与派系较浅 | 将任务条件、分支、奖励和冷却外置到剧本数据 |
| P2 | 美术与可访问性 | 目前只有一张首页原型图，地图/头像仍是原型资产 | 由作者确认风格后批量生产，并补替代文本、色盲与缩放检查 |
| P3 | 战术/RPG/MMO | 策略联机已有局域网 MVP；战术、RPG、MMO 与生产级联机仍未完整实现 | 分版本建设房间持久化/账号安全与后续模式，避免混合验收 |

## 部署与 Git 前检查

1. 先让仓库所有者确认玩法方向、首页美术和上述未完成范围。
2. 检查当前大批量改动，按“存档/AI/玩法/前端/文档”拆分提交，便于审阅和回滚。
3. 在干净环境运行全套测试、前端构建和 `build.cmd`，试玩新开局、读旧档、观战及一年推进。
4. 核对生成美术的使用授权与仓库许可；不要提交临时日志、构建目录或本地存档。
5. 作者明确同意后再推送分支并开 Pull Request；目前没有自动提交、推送或公网部署。
